Platform Overview & Security Architecture

SafeSync is a zero-compromise encrypted cloud storage platform. Every file is protected by two independent security layers before it touches the database — a user-chosen password and an ECC-based key-wrapping scheme — so that even if one layer is compromised, the other keeps the data safe.

ECC is invisible to the user. You only type your file password. The server uses the stored private key to unwrap the DEK automatically. If the GCM authentication tag fails, the download is rejected immediately — detecting any tampering with the ciphertext.

🤖 Adaptive Cryptographic Policy Engine

At upload time the engine automatically evaluates four signals and selects the optimal cipher without any user input.

Signal What is measured Effect on cipher
File extension .pdf .py .env .csv → HIGH sensitivity;
media files → LOW; everything else → MEDIUM		 HIGH → forces AES-256-GCM + short share window
File size Plaintext byte count read at upload ≤ 512 B + low/med + low risk → ECIES-DIRECT;
≤ 10 MB + low + desktop → AES-128-GCM;
all others → AES-256-GCM
User risk score 0.0–1.0 from: account age + activity burst (24 h) + sharing breadth (7 d) > 0.7 → forces HIGH + AES-256;
> 0.4 → escalates to AES-256

🔐 Cryptographic Primitives

File Encryption (Adaptive)

  • ECIES-DIRECT: file bytes encrypted via ECIES DEM (no AES)
  • AES-128-GCM: 128-bit key, AEAD, low-risk desktop files
  • AES-256-GCM: 256-bit key, AEAD, default for all others
  • 96-bit random nonce per file (AES modes)
  • GCM auth tag detects ciphertext tampering

Key Wrapping — ECIES / SECP256R1

  • Curve: NIST P-256 (SECP256R1)
  • Ephemeral ECDH per upload
  • KDF: HKDF-SHA-256 → 256-bit wrap key
  • Wrap cipher: AES-256-GCM (DEK wrap)
  • 256-bit ECC ≈ 3072-bit RSA security

Password Layer — PBKDF2

  • PBKDF2-SHA256 with Django defaults
  • Hash stored; plaintext never persisted
  • Verified before any crypto operation
  • 8–64 characters enforced
  • Independent of ECC layer

Legacy Path — AES-128-ECB

  • Original PoC cipher (pre-GCM era)
  • Backward-compatible download only
  • No authentication tag (tamper-blind)
  • Requires exact 16-char password
  • No new files created in ECB mode

👑 ECC Key Lifecycle

  1. Auto-provision: On your first file upload, SafeSync generates a SECP256R1 key pair and stores both keys in the database. No manual action needed at ECC Keys.
  2. Per-file ephemeral ECDH: A fresh ephemeral key pair is generated for each upload. The ECDH shared secret is derived between the ephemeral private key and your stored public key, then fed through HKDF-SHA-256 to produce a 256-bit wrapping key. Only the ephemeral public key is stored — the ephemeral private key is discarded immediately after wrapping.
  3. DEK recovery: At download time the server uses the stored ephemeral public key and your account private key to reconstruct the identical ECDH secret and unwrap the DEK without ever persisting the DEK in plaintext.
  4. Regeneration: You may regenerate your key pair from the ECC Keys page. After regeneration, existing files cannot be decrypted (the old private key is replaced). Only regenerate if you have a specific reason to rotate.

🔁 File Sharing & Access Control

  • Transfers are only allowed between registered, authenticated users.
  • HIGH sensitivity files are blocked from being shared (enforced server-side).
  • Every share link carries a policy-derived expiry timestamp (12 / 48 / 72 hours).
  • Expired links are rejected at download time with a clear error message.
  • The receiver must still pass the password gate to decrypt the file — the file password is never transmitted in the share itself.
